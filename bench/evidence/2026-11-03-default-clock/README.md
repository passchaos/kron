# Default Clock dispatch实验

目标继续是在相同完整输出/完成边界下超过Foundation/logging + spdlog和+tracing。两种生产候选已撤回，当前Clock/Runtime恢复0dfdf10。首候选在Clock.realNow每次读取当前real_now并与private realDefault判等；default分支直接调用同realDefault逻辑，custom路径保留原callback/context。没有create时cached flag，monotonic/zero、std.Io userdata/vtable、i96→i64 clamp、capture成功后/submit前timestamp时点保持。

当前default本来就vDSO优先，不把clock_gettime名字当作每事件必syscall。候选省的是可选Clock callback/可能的传参frame；Io now与vDSO及完整精度仍在。Static StandardClock/Native/TSC仍显式选择，旧clock-only pilot区间重叠不继承任何收益资格。

基线0dfdf10的源码和之前release-RMW binary匹配后冻结；原Clock2项Safe通过。独立public clock_dispatch tests覆盖14组i96边界/相邻值、不同Io身份、callback内/外default-custom切换、zero/monotonic、Runtime.nowNs以及Managed/instance/capture/error边界；每个阶段源码/binary/hash绑定。所有编译和tests结束后才测量。

额外custom_reference.zig只用于同std.Io系统clock的observable custom callback控制，按线程记录callback数并要求exact events+warmup。这个TLS计数防止wrapper与default合并，两个before/after都包含相同计数；default真实对照仍使用原reference benchmark。完整JSON由独立oracle核验，custom控制不当作Foundation排名，也不测Native/TSC/Zero替代语义。

首40项shared E-core full-process PMU核对4,040,000条JSON。instructions约减少0.09%，四组cycles与多数written-close不确定，Mmap P4关闭吞吐约0.992×局部负向。首E-core完整160项核对16,160,000条JSON，0组候选领先/1组baseline领先/15不确定，SPSC Mmap P4 sampled约0.939×负向；全部负向保留。没有因defaultcall3→2就取得保留资格。

首候选完成480项核对48,480,000条物理JSON：Ecore默认1组baseline领先/15不确定，Pcore2组baseline领先/14不确定，schema8组全不确定；observablecustomcallbackPMU有MmapP1局部负向。新defaultcallback减少不等于端到端收益，全部source/clockcall额外控制独立保存。

第二候选只在Runtime.nowNs内部调用点和private realDefault helper使用always_inline，公开Clock.realNow/now仍普通可取地址fn；custom慢路使用显式Io字段initializer snapshot，默认有机会只读两字段而不materializeinputIo。新增callback内替换Runtime.io的第9项回归在原baselineSafe与新variantFast通过，输入参数仍原Io/下一call新Io；publicfnptr类型comptime校验保留。相关Safe12steps57tests通过。尚需actualcodegen和完整流程，不能从always_inline词汇推收益。

内部inline版actualcode确认defaultIo inputcopy/contextload消失，customprivatecopy保留且新alias回归通过。首40项shared PMU的instruction配对速度比约1.0013..1.0014，吞吐/周期全部inconclusive；不能以输入copy删掉推速度。Ecore默认完整160项核对16,160,000条JSON，0组候选领先、3组baseline领先、13不确定（sharedMmapP1sampled、SPSCMmapP1/P4sampled负向），保存所有慢值与原source身份。

## 最终决定

两个版本总960项核对96,960,000条物理JSON，所有default、schema、observablecustomcallback控制原始数据完整保留，customcounts均exact events+warmup。首版default稳定收益为零且Ecore1/Pcore2负向；内部版defaultEcore3负向，Pcore16组全不确定。schema的个别局部win不能覆盖default/custom的反例，所有field/clock/frame/IOcopy静态事实不推导整体胜出。

Clock.realNow selector、私有always_inline/Io snapshot和Runtime callsite强制inline全部生产撤回。保留tests/clock_dispatch.zig九项回归与test-clock-dispatch build入口，原默认Clock provider、调用次数/时点、精度以及custom回调完整接口保持，未更新Foundation排名。decision.json记录各matrix，currentrestore验证/包分发另列日志，未重复未改生产的全库故障gate。

下一独立已确认候选是TLS leave的inactive slot冗余清理，研究在next-tls-inactive-slot.md；recordpin聚合发现已有完全同机制负向，留档避免重复。当前仍未全面超过两个Foundation组合，也未实现下一TLS机制。

恢复基线后test-clock-dispatch/capture/logging/deadline为12steps57tests通过，9项独立Debug/Fast通过，源码分发五freshconsumer模式2steps通过。生产Zig源逐文件hash与0dfdf10相同，build只加入test入口，不宣称全库故障gate重跑。qualification.json记录最终test/build/source身份与失败候选决定；没有因选中某一赢的schema组改变目标范围。
