# Shared admission分片候选设计（未实施）

基线100万P4 shared的约10K cpu_atom cycle样本中，begin约12.61%、reserve约10.67%、submitSafeDestination约13.45%。这些比例不代表可相加的提速。下一候选先降低普通admission共享计数的竞争，必须单独检查P1额外访问与每Runtime约4KiB成本。

保持公共Logger API和未reserve捕获仍被flush cut纳入的契约。普通shared可以按OS Thread.Id哈希映射固定64个独占64B cacheline的flags/count原子word；碰撞增加竞争，不要求attach、不引入线程数量限制。Zig Linux getCurrentId已经TLS缓存，额外缓存纯哈希值，不长期TLS保存Runtime指针。

普通获取：SC读取global flags/revision；开放时对选定片CAS增加count，再SC复查global。只有相同revision且开放才能进入TLS/capture；其他情况准确释放原片并重试/拒绝。TLS Frame保存原片token，resource/view释放和frame退出之后再减少原片count，不能重新哈希。片的最后一个admission在cut/closing时wake共享epoch；closing还notify worker。

cut持有原cut_mutex：先发布global cut/revision，再冻结全部片，随后逐片等待零，沿用原thread registry和reservation target snapshot。结束cut先清各片cut，保留closing，最后用保留flags的CAS清global cut并推进revision/wake。跨越cut的获取通过SC复查回退；通过复查而仍在capture的调用持有片count，必须被等待。

关闭沿用当前collector约束：关闭thread/config入场、冻结所有shared片，最后发布global closing/revision及Runtime closing状态。collector在global closing成立之后才冷扫描所有片和原thread/config counts，此时片count只会下降，零值稳定。waitAdmissions只等shared，不能等待包括配置调用自身的综合总数。global revision不能继续被原count_mask观察者当成active count；所有观察点必须审计替换，configuration_gate继续原单word协议。

候选集中在src/core/admission.zig和runtime.zig，原configuration_gate/SPSC/control deadline协议保留。验证需要确定性暂停点：global初读后、片CAS后复查前、成功admission后reserve前；跨片/同片碰撞，closing与endCut并发，最后shared admission唤醒sleeping worker，nested Runtime token/view平衡，阻塞满队列的capture被cut等待时worker继续排空，deadline停止等待后后台继续完成。

相关现有入口：runtime_admission_view回归、admission TLS/closing测试、runtime最终channel唤醒、test-deadline、test-integration、test-configurations/transactions、单线程。通过最小握手测试后，才运行完整故障/包gate及P1/P4/P16资源和完整文件before/after；最后用同一源码、默认CRC对两个Foundation前端复测。当前这份设计没有实现或性能资格。
